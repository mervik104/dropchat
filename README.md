# DropChat

Личный мессенджер для передачи текста и файлов между своими устройствами без
аккаунтов, паролей и регистрации. Работает как веб-приложение: React-клиент,
Cloudflare Workers, D1 и прямой WebRTC-канал между устройствами.

- Production UI: <https://drop.mervik.ru/>
- Worker: <https://dropchat.stepanenkoboris.ru>
- API health: <https://dropchat.stepanenkoboris.ru/api/health>

## Возможности

- **Без аккаунтов.** Устройство получает случайный `deviceId` и секрет; на
  сервере хранится только SHA-256 секрета.
- **Обнаружение устройств.** Устройства с одним публичным IP попадают в раздел
  «Рядом».
- **Связывание.** Запрос из «Рядом» или одноразовый код приглашения.
- **Текст.** Сообщения доставляются через Worker, D1 и WebSocket; при открытом
  локальном канале текст уходит напрямую между устройствами.
- **Файлы.** Можно выбрать несколько файлов сразу. Автоматический выбор
  транспорта: сначала WebRTC, при неудаче — Google Drive через `drive-gateway`.
- **Статусы транспорта.** В сообщениях видно, доставлено ли оно «локально» или
  через «интернет»; локальные сообщения выделены цветом.
- **Локальная история.** P2P-сообщения и локальные file-metadata сохраняются в
  `localStorage` устройства и не исчезают после перезагрузки страницы.
- **Быстрый старт.** При повторном запуске приложение сразу показывает
  закешированных собеседников, а сервер синхронизируется в фоне.
- **Индикатор соединения.** Пока сервер недоступен или идёт переподключение,
  внизу слева виден спиннер и «Соединение…»; в списке чатов при этом показывается
  баннер «Доступен только локальный режим». Клиент продолжает переподключаться.
- **Настройки устройства.** Имя, невидимый режим, экспорт/импорт identity,
  отвязка собеседников.
- **Ограничения и очистка.** Квоты на upload/хранение, rate limits и retention
  cron на 30 дней.
- **PWA.** Манифест, иконки и service worker кешируют оболочку приложения для
  повторного запуска при плохой сети.
- **Адаптивный UI.** Поиск по устройствам и чатам, обновление списка, мобильная
  и десктопная раскладка с учётом экранной клавиатуры.
- **Меню чата.** Отвязка устройства доступна из меню поверх сообщений; меню
  закрывается по клику вне и Escape, ошибки действия показываются уведомлением.
- **Уведомления в интерфейсе.** Непрочитанные чаты поднимаются выше, получают
  счётчик, звуковой сигнал и префикс в заголовке вкладки. Уведомления не
  сохраняются на сервере и сбрасываются при открытии чата.
- **Защита интерфейса.** Error boundary показывает экран восстановления вместо
  пустого/чёрного экрана при ошибке рендера.
- **Восстановление загрузки.** При потере ответа на часть файла клиент
  синхронизирует offset с сервером; постоянные 4xx не ретраятся.

## Архитектура

```text
┌──────────────────────────┐       HTTPS/WebSocket       ┌─────────────────────┐
│ web (React + Vite)       │ ──────────────────────────> │ worker (Hono)       │
│ GitHub Pages             │                             │ Cloudflare Workers  │
└────────────┬─────────────┘                             └──────┬──────┬───────┘
             │                                                  │      │
             │ WebRTC DataChannel                               │      │ service binding
             ▼                                                  ▼      ▼
┌──────────────────────────┐                             ┌──────────┐ ┌──────────────────┐
│ другое устройство        │                             │ D1       │ │ drive-gateway    │
│ тот же DropChat          │                             │ SQLite   │ │ Google Drive API │
└──────────────────────────┘                             └──────────┘ └──────────────────┘
```

- **web** — React 18, Vite, TypeScript. Identity хранится в `localStorage`.
- **worker** — Hono на Cloudflare Workers: auth, устройства, связи, сообщения,
  файлы, rate limits, retention и CORS. WebSocket-соединения обслуживает
  Durable Object `Hub`.
- **drive-gateway** — отдельный Worker для Google Drive: обновляет OAuth-токен
  и создаёт upload-сессии. Основной Worker ходит к нему через service binding
  `DRIVE`; публичный домен требует `X-Internal-Key`.
- **shared** — общие типы и протокол.
- **web/src/platform** — тонкие обёртки браузерных API: WebSocket, WebRTC,
  clipboard, storage.

## Транспорт сообщений и файлов

Выбор транспорта автоматический; пользователь не переключает режимы вручную.

### Текст

1. Если для чата уже открыт WebRTC DataChannel, сообщение отправляется через
   него и ждёт ACK от получателя.
2. Только после ACK сообщение помечается как `локально` и сохраняется в
   локальную историю.
3. Если ACK не пришёл за 3 секунды или канал закрылся, клиент пробует серверный
   путь. Если и он недоступен, сообщение становится «Ошибка отправки», а не
   ложным зелёным.
4. Серверный путь использует `POST /api/chats/:peerId/messages`, D1 и WebSocket.
   В UI это `интернет`.

### Файлы

1. Клиент пытается отправить файл по WebRTC.
2. Если DataChannel не открылся за 8 секунд или P2P завершился ошибкой,
   включается облачная загрузка в Google Drive. Таймер относится только к
   установке соединения: уже начатая P2P-передача не обрывается и не дублируется
   облаком из-за длительности файла.
3. Облачная загрузка идёт частями по 32 МиБ с повтором и возможностью отмены.
   Каждая часть повторяется до шести раз с exponential backoff и jitter;
   `429`/`5xx` учитывают `Retry-After`, а истёкшая Google-сессия возвращает
   `410`, а не бесконечный `502`. При выборе нескольких файлов каждый получает
   отдельный прогресс и отмену; одновременно выполняется одна загрузка,
   остальные ждут в очереди. Отмена прерывает текущий HTTP-запрос и не
   запускает `complete`.
4. P2P-файл не хранится на сервере. В D1 сохраняется только metadata сообщения;
   если сервер недоступен, сообщение остаётся локальным в открытом чате.
   Несколько P2P-файлов отправляются по одному DataChannel последовательно,
   чтобы кадры разных передач не перемешивались. Отмена одного файла посылает
   `cancel` с id передачи, не закрывает канал и не прерывает встречный файл.
   Если буфер не уменьшается 30 секунд, передача считается зависшей и уступает
   место следующей.
5. Отправитель ждёт ACK получателя. Файл без ACK не считается доставленным и
   уходит в облачный fallback.
6. P2P-файлы ограничены 512 МиБ; большие файлы автоматически идут в облако.
7. Принятый файл пишется в OPFS и скачивается браузером; при отсутствии OPFS
   используется Blob fallback.

### Локальный канал

- При открытии чата клиент заранее поднимает DataChannel через штатный
  WebSocket signaling.
- Инициатор соединения — устройство с меньшим `deviceId`, чтобы избежать
  одновременных offer.
- Сигналинг идёт через Cloudflare, но содержимое сообщений и файлов при
  открытом DataChannel — напрямую.
- Локальные сообщения сохраняются в браузере (до 500 последних, 30 дней) и
  восстанавливаются при следующем открытии чата.
- Доставка локального текста подтверждается ACK; зелёный статус `локально`
  означает, что получатель принял сообщение.
- STUN используется, TURN не настроен.

## Требования

- Node.js `>=22.22.2`; рекомендуется Node.js 24.
- npm.
- Cloudflare-аккаунт для деплоя Worker'ов.

## Быстрый старт

```sh
npm ci
cp worker/.dev.vars.example worker/.dev.vars
cp drive-gateway/.dev.vars.example drive-gateway/.dev.vars
npm run db:migrate:local
```

Запустить Worker и gateway одной командой:

```sh
npm run dev:workers
```

Во втором терминале:

```sh
npm run dev --workspace @dropchat/web
```

Открыть <http://127.0.0.1:5173/>. Vite проксирует `/api` на
`http://127.0.0.1:8787`.

Для облачных файлов заполните `drive-gateway/.dev.vars` по
[`docs/google-cloud-setup.md`](docs/google-cloud-setup.md). Без Google Drive
локальный текст и P2P-файлы продолжают работать.

Никогда не коммитьте `.dev.vars`, токены и secrets.

## Конфигурация

### Worker vars

Основные значения находятся в `worker/wrangler.jsonc`:

| Переменная | Default | Назначение |
| --- | --- | --- |
| `WEB_ORIGIN` | production origin | Разрешённый CORS origin |
| `CLOUD_UPLOADS_ENABLED` | `true` | Включить облачные файлы |
| `RETENTION_DAYS` | `30` | Срок жизни сообщений и файлов |
| `MAX_FILE_SIZE` | `53687091200` | Максимальный размер файла, 50 ГиБ |
| `PER_DEVICE_UPLOAD_PER_24H` | `53687091200` | Upload-квота за 24 часа, 50 ГиБ |
| `PER_DEVICE_STORED_TOTAL` | `53687091200` | Хранилище на устройство, 50 ГиБ |
| `INVITE_CREATE_LIMIT_PER_HOUR` | `20` | Создание invite-кодов |
| `GLOBAL_STORED_TOTAL` | `1099511627776` | Общее хранилище, 1 ТиБ |
| `*_LIMIT_*`, `*_PER_*` | см. конфиг | Rate limits |

### Secrets

Основной Worker:

- `SERVER_SALT`
- `DOWNLOAD_SIGNING_KEY`
- `INTERNAL_KEY`

`drive-gateway`:

- `GOOGLE_CLIENT_ID`
- `GOOGLE_CLIENT_SECRET`
- `GOOGLE_REFRESH_TOKEN`
- `DRIVE_FOLDER_ID`
- `INTERNAL_KEY` — тот же, что у основного Worker

`INTERNAL_KEY` должен совпадать в обоих Worker. Значения задаются через
`wrangler secret put` и никогда не попадают в репозиторий.

### Web build

- `VITE_API_URL` — полный URL Worker без `/api` на конце.
- `VITE_BASE` — базовый путь сборки; для custom domain: `/`.

## Деплой

Порядок: **drive-gateway → worker → web**. Подробный runbook:
[`docs/deploy-first.md`](docs/deploy-first.md).

```sh
npx wrangler d1 migrations apply dropchat --remote --config worker/wrangler.jsonc
npm run deploy --workspace @dropchat/drive-gateway
npm run deploy --workspace @dropchat/worker
```

Web деплоится через GitHub Actions:

1. CI workflow запускает typecheck, lint, tests, coverage и build на каждый push.
2. После успешного CI на `main` workflow `Deploy Pages` собирает `web/dist`.
3. В GitHub repository variables должен быть задан `VITE_API_URL`; base path
   для custom domain `drop.mervik.ru` — `/`.

Проверка после деплоя:

```sh
curl -sS https://dropchat.stepanenkoboris.ru/api/health
# {"ok":true,"app":"DropChat"}
```

## Ограничения

- Для первого запуска нужна сеть, чтобы зарегистрировать identity. Повторный
  запуск использует локальный кеш и работает быстрее при плохой связи.
- Нет TURN-сервера: P2P работает только при доступном прямом WebRTC-соединении.
- Локальный DataChannel живёт, пока открыта страница. После перезагрузки или
  холодного старта без интернета нужен онлайн-сеанс для signaling.
- Локальная история хранится только на этом устройстве в `localStorage`, не
  синхронизируется на сервер и удаляется при очистке данных браузера.
- P2P-файлы ограничены 512 МиБ. Приём использует OPFS, но в браузерах без OPFS
  остаётся Blob fallback в памяти.
- Основные запросы списка чатов, истории и загрузок имеют таймауты; некоторые
  служебные операции (регистрация, профиль, приглашения) всё ещё ждут сетевого
  таймаута браузера.
- Облачная загрузка не продолжается автоматически после полной перезагрузки
  страницы: состояние на сервере есть, но файл нужно выбрать снова.
- При отвязке устройства активные и ожидающие uploads отменяются; сервер также
  отклоняет части, завершение и выдачу ссылок на файлы для уже отвязанного peer.
  Ссылки, выданные получателю до отвязки, перестают работать.
- Проверка квоты и создание записи загрузки выполняются одной транзакцией D1,
  поэтому параллельные init не превышают лимиты.
- Уведомления о непрочитанных работают только в открытой вкладке: звук, счётчики
  и заголовок локальны и не синхронизируются между устройствами.
- Service worker кеширует только оболочку приложения, не сообщения и не файлы.
  Первый холодный запуск без сети всё равно требует установки/посещения.
- Google Drive принадлежит владельцу сервиса; это personal-first приложение,
  не multi-tenant сервис.

## Безопасность и приватность

- Секрет устройства не хранится на сервере: только его SHA-256.
- `ip_group` — необратимый хеш IP, нужный для обнаружения устройств.
- CORS разрешает только `WEB_ORIGIN` и `localhost` в разработке.
- Все изменяющие API-маршруты защищены Bearer-токеном, rate limits и проверкой
  связей.
- Сообщения и metadata файлов удаляются retention cron через 30 дней.
- Содержимое P2P-файлов не проходит через сервер.

Подробнее: [`docs/privacy.md`](docs/privacy.md).
